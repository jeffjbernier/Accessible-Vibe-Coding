# Using These Rules in Cursor, Windsurf, and Copilot

Claude Code loads the two rulesets in this repo as [Agent Skills](https://code.claude.com/docs/en/skills) — a folder with a `SKILL.md` in it, discovered automatically, invoked by description. No other assistant works that way. Cursor, Windsurf, and GitHub Copilot each read a *rules file*: plain markdown, a different path per tool, a different frontmatter dialect on top, and different conditions under which it gets injected into the prompt at all.

That's what `rules/accessibility-rules.md` and `rules/form-rules.md` are for. Same content as the skills, frontmatter stripped, repo-relative paths rewritten to absolute URLs so they still resolve once copied out.

[INSTALL.md](../INSTALL.md) has the short version — copy this file here, add that frontmatter. This guide is the long version: what each tool actually does with the file once it's in place, which size caps will silently truncate or reject it, how to confirm it fired, and where each one will quietly do nothing.

---

## What transfers, and what doesn't

Four things are true on every platform in this guide. Read them before you spend an afternoon wondering why nothing changed.

**Rules never reach inline completions.** Cursor's docs are explicit that rules apply to Agent chat only, not Tab, not Inline Edit, not Bugbot PR review. VS Code's Copilot docs say the same: "Custom instructions are not taken into account for inline suggestions as you type in the editor." Ghost text is generated by a small, fast, context-starved model that never sees your ruleset. Every accessible-by-default guarantee in this repo applies to what the *agent* writes, and to nothing you autocomplete by hand.

**A rules file is a strong prior, not a compiler flag.** The model reads the ruleset and mostly complies. It does not *validate* against it. A rule file raises the floor; it does not guarantee the floor. That is the entire argument for the layered workflow in the [repository README](../README.md) — automated scanning, keyboard testing, screen reader testing, and testing with disabled users all still apply, unchanged.

**Size caps are real and mostly silent.** Windsurf caps a workspace rule file at 12,000 characters. Both files in `rules/` exceed that today. Nothing warns you — see [Windsurf](#3-windsurf-devin-desktop) below.

**Trigger conditions are where these actually fail.** Nearly every "the rules aren't working" report across all three tools comes down to the file loading fine but never being *selected* for the turn. Set the always-on trigger. Then verify it, with the canary test in [Section 6](#6-verifying-it-actually-fired).

## 2. Cursor

### Where the file goes in Cursor

Project rules live in `.cursor/rules/`, and **only `.mdc` files are read**. A `.md` file in that folder is ignored with no error, no warning, and no entry in the rules pane. Renaming on copy is not cosmetic:

```bash
mkdir -p .cursor/rules
cp Accessible-Vibe-Coding/rules/accessibility-rules.md .cursor/rules/accessibility-rules.mdc
cp Accessible-Vibe-Coding/rules/form-rules.md .cursor/rules/form-rules.mdc
```

For rules that follow you across every project instead, use **Customize → Rules** in the sidebar (stored on your Cursor account, syncs between machines) or `~/.cursor/rules` (machine-local, does not sync). Project scope is the better home for these two — they're checked-in configuration, and your teammates and CI agents get them for free.

### Frontmatter, and the four behaviors it produces

Cursor has exactly three frontmatter fields — `alwaysApply`, `description`, `globs` — and the combination decides when the rule loads:

| `alwaysApply` | `description` | `globs` | Behavior |
| --- | --- | --- | --- |
| `true` | — | — | Always included. Description and globs are ignored. |
| `false` | — | set | Attached when a matching file is in context. |
| `false` | set | — | The agent reads the description and decides. |
| `false` | — | — | Only when you `@`-mention the rule by name. |

For `accessibility-rules`, use the first row and nothing else:

```markdown
---
alwaysApply: true
---
```

That's the whole frontmatter. Don't add a `globs` line alongside it — Cursor staff have pointed at exactly that combination as a cause of rules failing to inject, and globs are ignored under `alwaysApply: true` anyway.

`form-rules` can go either way. Always-on is the safe default. If you'd rather scope it, drop `alwaysApply` to `false` and attach it to the paths where forms actually live:

```markdown
---
globs: app/views/**/*.erb, src/components/**/*.tsx
alwaysApply: false
---
```

**Glob syntax is the single most common way to break this.** Cursor's frontmatter is not strictly YAML. Globs are a bare comma-separated list — no brackets, no quotes. `globs: ["src/**/*.tsx"]` and `globs: "src/**/*.tsx"` both parse to something that matches nothing, silently. You will find community posts recommending the array form; they're wrong, and Cursor staff have said so directly.

The third row of that table — description-only, "apply intelligently" — is a coin flip for a ruleset like this, and not one worth taking. The premise of `accessibility-rules` is that it fires when nobody mentioned accessibility. Handing the model a description and asking it to notice is the exact failure mode the skill was written to prevent.

### Length

Cursor's documented guidance is 500 lines per rule. Both files clear it. If you fork and grow one past that, split it by section rather than letting one file sprawl — `.cursor/rules/` supports subfolders, and rules are identified by full path, so same-named files in different folders don't collide.

### `.cursorrules` is legacy

The old root-level `.cursorrules` file is still read but on the way out, and the current docs have dropped it entirely. One trap worth knowing: if `.cursor/rules/*.mdc` files exist, they win, and `.cursorrules` looks like it's being ignored. If you're migrating, move the content into a `.mdc` and delete the old file rather than keeping both.

## 3. Windsurf (Devin Desktop)

Windsurf is now Devin Desktop under Cognition, and `docs.windsurf.com` redirects to `docs.devin.ai/desktop/`. The product still works the way you remember; the paths and the docs URL moved.

### Where the file goes in Windsurf

| Path | Status |
| --- | --- |
| `.devin/rules/*.md` | Current. Write here. |
| `.windsurf/rules/*.md` | Legacy fallback, still read |
| `.windsurfrules` (single root file) | Legacy, still read |
| `~/.codeium/windsurf/memories/global_rules.md` | Global rules, 6,000 character cap |

`.devin/` takes precedence, and both directories load together.

### Frontmatter

Windsurf uses `trigger:` where Cursor uses a boolean:

```markdown
---
trigger: always_on
---
```

The four values are `always_on`, `glob` (which also needs a `globs:` line), `model_decision` (which needs a `description:` for the model to decide on), and `manual` (activated by typing `@rule-name`). Use `always_on` for accessibility, for the same reason as Cursor.

### The 12,000-character cap — both files need splitting

This is the one real obstacle in this guide. Windsurf caps each workspace rule file at 12,000 characters. `accessibility-rules.md` is ~16,700 and `form-rules.md` is ~21,100. Over the cap, the tail is not honored, and nothing tells you which half the model got.

Split each at a section boundary, repeating the header block so part two still carries its own "when this applies" framing. For v1.0.0:

```bash
mkdir -p .devin/rules
R=Accessible-Vibe-Coding/rules

sed -n '1,254p' $R/accessibility-rules.md > .devin/rules/accessibility-rules-1.md
{ sed -n '1,33p'  $R/accessibility-rules.md
  sed -n '255,$p' $R/accessibility-rules.md; } > .devin/rules/accessibility-rules-2.md

sed -n '1,269p' $R/form-rules.md > .devin/rules/form-rules-1.md
{ sed -n '1,40p'  $R/form-rules.md
  sed -n '270,$p' $R/form-rules.md; } > .devin/rules/form-rules-2.md
```

That puts the split before "Recommend when appropriate" in the accessibility rules, and before section 8 in the forms rules — four files in the 5,300–11,500 character range, each comfortably under the cap.

Add `trigger: always_on` frontmatter to all four, then confirm nothing crept over:

```bash
wc -c .devin/rules/*.md
```

**Those line numbers are pinned to v1.0.0 and will drift** every time the skills change and `rules/` is rebuilt. Don't reuse them blind after a `git pull` — re-run `wc -c`, and if a part is over 12,000, move the split to the previous `##` heading.

## 4. GitHub Copilot

Copilot has more instruction file types than the other two, and they are not supported evenly across IDEs. The distinction matters more than the syntax.

### Repo-wide: `.github/copilot-instructions.md`

This is the only instruction type GitHub supports on every surface — github.com chat, VS Code, Visual Studio, JetBrains, Xcode, Eclipse, the Copilot coding agent, and Copilot code review. If you install one thing, install this one:

```bash
mkdir -p .github
cat Accessible-Vibe-Coding/rules/accessibility-rules.md >> .github/copilot-instructions.md
```

No frontmatter; Copilot takes plain markdown here. The setting that governs it, `github.copilot.chat.codeGeneration.useInstructionFiles`, defaults to on, so there's nothing to enable unless someone turned it off.

GitHub's guidance is that this file should be "no longer than 2 pages." Both rulesets blow past that, and there's no published hard cap to hit. In practice a long repo-wide instruction file works; the cost is dilution, since every instruction competes for the model's attention on every request. If you're appending both rulesets plus your own house style, put `accessibility-rules` here and scope `form-rules` by path instead.

### Path-scoped: `.github/instructions/*.instructions.md`

Supported in VS Code, Visual Studio, JetBrains, Xcode, the coding agent, and code review — but **not** in github.com chat. Good fit for `form-rules`:

```bash
mkdir -p .github/instructions
cp Accessible-Vibe-Coding/rules/form-rules.md \
   .github/instructions/form-rules.instructions.md
```

Then add the `applyTo` glob at the top. Multiple patterns go comma-separated *inside one string*:

```markdown
---
applyTo: "app/views/**/*.erb,src/components/**/*.tsx"
---
```

`applyTo: "**"` makes it universal. Omit `applyTo` entirely and the file becomes manual-attach only, which is almost never what you want here.

### JetBrains

The JetBrains plugin reads `.github/copilot-instructions.md`, plus a machine-local `global-copilot-instructions.md` for rules you want in every project. Both are on by default once the file exists.

GitHub's support matrix also lists JetBrains as supporting path-scoped `.instructions.md` and `AGENTS.md`, but the IDE-specific how-to page documents neither. The matrix is the newer source and probably right — test `applyTo` with the canary below before you depend on it in JetBrains.

### What Copilot won't do

Inline completions, as covered up top. Also worth knowing: VS Code's `chat.promptFilesLocations` and `chat.instructionsFilesLocations` settings both carry deprecation notices pointing toward skills, so the VS Code customization surface is in motion. `.github/copilot-instructions.md` is the stable choice while that settles.

## 5. AGENTS.md — the widest reach for the least work

[AGENTS.md](https://agents.md/) is a plain markdown file at the project root with no frontmatter and no schema — "a README for agents." It is read by Copilot (every surface but Visual Studio), Windsurf/Devin, Cursor, Codex, Jules, Junie, Aider, Zed, RooCode, and a long tail of others, across tens of thousands of projects.

If you support a mixed team on mixed tools, this is the highest-leverage single file in this guide:

```bash
cat Accessible-Vibe-Coding/rules/accessibility-rules.md >> AGENTS.md
cat Accessible-Vibe-Coding/rules/form-rules.md >> AGENTS.md
```

Agents read the nearest `AGENTS.md` up the directory tree, so a package-level file overrides the root for that package. Cursor also treats `CLAUDE.md` this way — and applies it unconditionally, regardless of any `alwaysApply` setting.

The tradeoff is that AGENTS.md is always-on and unscoped by design. There's no way to attach `form-rules` only to your template directory. For a repo where forms are most of the surface, that's fine. For a large repo where they aren't, the path-scoped options above are the better tool.

## 6. Verifying it actually fired

Each platform gives you something, and none of it is great.

| Platform | What it shows you |
| --- | --- |
| Cursor | The context indicator tooltip in the composer lists active rules for the conversation — though it truncates when you have many. **Customize → Rules** lists everything loaded and its type. |
| Windsurf | **Customizations → Rules** panel shows what's loaded. No per-response attribution. |
| Copilot | The **References** list on a chat response names `.github/copilot-instructions.md` when the instructions were included in the prompt. Same in VS Code and JetBrains. |

None of those tell you the model *complied*. For that, and for anything AGENTS.md, use a canary. Temporarily add one line to the top of the rules file:

```markdown
Begin your first reply in every conversation with the word: CONFIRMED
```

Open a fresh chat — not a continued one — ask for anything, and look for the word. Delete the line once you've seen it. It's crude and it is the only signal that survives every platform in this guide.

If the canary doesn't appear, work through these in order: wrong extension (`.md` in `.cursor/rules/`), malformed frontmatter (a missing closing `---` means the file silently doesn't load), bracketed or quoted globs, a size cap you're over, or a trigger set to something other than always-on.

## 7. Which destination to use

| Your setup | Install this |
| --- | --- |
| Cursor only | `.cursor/rules/*.mdc`, `alwaysApply: true` |
| Windsurf only | `.devin/rules/*.md`, `trigger: always_on`, split under 12,000 chars |
| Copilot, one IDE | `.github/copilot-instructions.md` + path-scoped `form-rules` |
| Copilot across IDEs | `.github/copilot-instructions.md` only — the one type supported everywhere |
| Mixed team, mixed tools | `AGENTS.md` at the root, plus tool-specific files for anyone who needs scoping |
| Claude Code | The skills, not these files. See [INSTALL.md](../INSTALL.md). |

Installing more than one is fine and usually redundant rather than harmful — a tool reads the file it knows about and ignores the rest. The cost is drift between copies, which the next section is about.

## 8. Keeping copies current

Everything under `rules/` is generated from `skills/<name>/SKILL.md` by `tools/build-rules.mjs`. Your copies inherit that: don't edit the copy expecting an update to preserve your changes, and don't open a pull request against `rules/` — the fix belongs in the skill.

To refresh:

```bash
cd Accessible-Vibe-Coding && git pull
node tools/build-rules.mjs   # only if you've forked and changed a skill
```

Then re-copy into whichever destination you used, re-run the Windsurf split if that's your platform, and re-add the frontmatter — the generator strips it, so every copy step drops it again. If you've customized your copy, diff before overwriting.

A note on `.mdc` specifically: the frontmatter Cursor expects isn't valid YAML, so formatters, linters, and editors that helpfully reformat frontmatter can rewrite `globs: a, b` into something Cursor no longer matches. After any tooling touches a `.mdc`, reopen it as plain text and confirm the three fields survived intact.

## 9. Known gotchas

- `.md` files in `.cursor/rules/` are ignored silently. The extension must be `.mdc`.
- Cursor globs are bare comma-separated values — no brackets, no quotes. The array form matches nothing and reports nothing.
- Don't pair `globs:` with `alwaysApply: true` in Cursor. The globs are ignored, and the combination has been implicated in rules failing to inject.
- `.cursorrules` loses to `.cursor/rules/*.mdc` when both exist, which reads as the legacy file being broken.
- Windsurf's cap is 12,000 characters per workspace rule file and 6,000 for global rules. Both files in `rules/` are over the workspace cap and must be split.
- Windsurf's paths moved to `.devin/rules/`. `.windsurf/rules/` and `.windsurfrules` still work as fallbacks, and `docs.windsurf.com` now redirects to `docs.devin.ai`.
- Copilot path-scoped `.instructions.md` files are not supported in github.com chat. Repo-wide is the only type supported on every surface.
- Copilot's `applyTo` takes multiple globs comma-separated inside a single quoted string, not as a list.
- No tool in this guide applies rules to inline ghost-text completions. Chat and agents only.
- A missing closing `---` on frontmatter means the file doesn't load, on every platform, with no error.
- The split line numbers in Section 3 are pinned to v1.0.0 and drift on every rebuild. Re-check with `wc -c`.
